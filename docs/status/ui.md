# 現況：介面（語言、字型、導覽、列表、專輯、來源篩選、頻譜圖）

本文件是此領域「目前狀態」的快照，不是日誌；維護規則同根目錄 `AGENTS.md`「本文件維護規則」：就地改寫既有條目、不寫日期／量測數字／除錯經過，設計細節放 `docs/adr/`。

### 介面

介面語言（ADR 0019）：設定 → 主介面最下面「語言」（跟隨系統／繁體中文／简体中文／日本語／English，`settings.json` 的 `language`，`settings_get/set_language`，切換後存 localStorage 並重新載入，其他視窗收 `app-language-changed`）。前端文字寫成 `tr('繁體原文')`；`src/lib/i18n/zh-CN.json` 由 `node scripts/i18n-catalog.mjs`（OpenCC twp→cn＋`zh-CN.terms.json`＋`zh-CN.overrides.json`）產生；`ja.json`、`en.json` 手寫（`tests/i18n-catalog.test.mjs`，`--missing` 列出缺句）。跟隨系統取 `navigator.languages` 第一個支援的語言，否則英文。Rust 後端訊息仍是繁體（使用者決定先不改）。分組標籤 `漢字` 不翻譯；後端「未知」與「本地」經 `displayUnknown()`（`src/lib/unknown-label.js`）顯示。

字型選擇（ADR 0042）：主介面（設定 → 主介面「字型」）、播放頁歌詞、工作列歌詞、浮動歌詞各自儲存家族名稱（`interfaceFontFamily`、`lyricsPreferences.fontFamily`、`taskbarLyrics.fontFamily`、`floatingLyrics.fontFamily`；`null`＝預設字型，沒裝的字型保留設定、繪製時退回預設）。四處共用 `src/lib/FontPicker.svelte`（清單與讀取狀態在 `<script module>`；純函式 `font-picker.js`；主介面在設定 → 主介面，三個歌詞分頁在「字體與大小」第一項）：搜尋框、第一列「預設（…）」（`defaultFontFamily` 依目標說出預設實際繪製 CJK 文字的家族：主介面＝預設字型串中第一個有 CJK 的已安裝家族、播放頁跟隨主介面字型、Windows 原生歌詞＝win.rs 的 CJK fallback 微軟正黑體、Android＝`fonts_list` 的 `systemDefault`〔`font_fallback.xml`／`fonts.xml` 的 sans-serif 與地區 CJK fallback〕；判斷不出時為「預設字型」）、選了立即套用。清單就是曲庫的 `PagedVirtualList`：分組列「繁體中文／簡體中文／日文／英文」依後端地區順序（搜尋時沒有結果的組不顯示）、點分組列開快速查找面板（以 `topLayerPopover` 放在 top layer，快速設定抽屜內外外觀與位置相同）、方向鍵＋Enter 選擇；列沿用曲庫的 `track-row` 樣式。每列一渲染就以自己的名稱子集繪製（`font-row-faces.js`，FontFace API，跨選單共用）；沒有子集的列直接用真正的家族；目前值標籤與套用用真正的家族。名稱子集：`player_fonts::name_subset`（subsetter）放 UserData `font-subsets/`、記錄在 schema v24 `font_subsets`；asset protocol 只開放該資料夾。只有打開選單才呼叫 `fonts_list`（`src-tauri/src/fonts.rs`，啟動時不掃描）：第一次（`needs_full_build`）先完成全部掃描與全部子集才回傳，期間顯示「讀取字型中…」；之後立即回傳 SQLite 快取（schema v22–v23 `font_files`／`font_faces`）與子集，背景只重讀新增、改變或 `PARSE_VERSION` 不同的檔案，送 `fonts-list-updated` 就地更新（`FONT_WORK` 一次只跑一個；流程以 `FontHost` 抽象可測）。無法顯示一般文字的字型不列出但仍可解析已存的設定；沒有 Unicode cmap 的舊字型依編碼分組。讀字型、書寫系統判斷（繁簡字形表 `han_forms.rs`）、地區排序與名稱語言在 `crates/player-fonts`（ttf-parser；`cargo run -p player-fonts --example list_fonts` 診斷）；排序依作業系統地區（不是介面語言）。門檻、流程與理由見 ADR 0042。套用：主介面 `<html>` 的 `--app-font-family`（`app.css` `--app-font-stack`）、播放頁 `--lyric-font-family`、Windows 原生歌詞 DirectWrite（`Look.font_family`）、Android WebView 以 FontFace API 載入選用家族的字型檔（asset protocol scope 只加入列出的字型檔與子集資料夾）、Android 浮動歌詞由 Rust 附上 `fontFaces` 後以 `Typeface.Builder` 建立（`LyricFonts.kt`）。待實機驗收：Windows 首次開啟的等待、「預設（…）」與原生歌詞換字型；Android 子集與 `@font-face`、`systemDefault`、浮動歌詞字型。

左側導覽：品牌固定在上，搜尋列是 `.sidebar-scroll` 的第一項（在「曲庫」之上），與導覽項目一起捲動，「設定」固定在底部；程式聚焦搜尋列一律經 `focusSidebarSearch`（`src/lib/sidebar-search-focus.js`，只捲動 `.sidebar-scroll`、含 `scroll-margin`，`tests/sidebar-search-focus.test.mjs`）；播放清單群組恆為展開。視窗寬 ≤ 820 CSS px（`src/lib/nav-panel.js` 的 `NAV_PANEL_MEDIA_QUERY`，Android 手機都在內）時工作區佔滿寬度，頂欄左側 MOE 標誌按鈕（`.nav-panel-toggle`，左右間距 `--nav-toggle-gap` 14 px，自圖示可見像素起算）切換導覽面板：同一個 `<aside class="sidebar">` 加 `.floating-surface`，fixed 疊在內容上，上緣貼標題列、左緣貼視窗、下緣停在播放列時間軸帶頂端（`--nav-panel-dock-overhang`＝`--dock-timeline-band`，見「播放進度時鐘」），四角直角、保留陰影，160 ms 淡入（遵循 reduced-motion）；點外部、Esc、選任何項目後關閉，放寬視窗或開啟播放頁時自動關閉，關閉時 inert。同一斷點下頂欄「重新整理」只顯示圖示。Release CDP 寬／窄驗收尚待補做。

浮動面板外觀：快速設定、窄版導覽面板（`.sidebar.floating-surface`）、睡眠定時等面板只透過 `.floating-surface` 取得背景（`--text-inverse` 依 `--quick-settings-opacity` 混合）、`--quick-settings-blur`、陰影與圓角（變數掛在 `.app-shell`）；以 `.sidebar` 為主體設定 background／backdrop-filter 的規則必須加 `:not(.floating-surface)`，各面板自身不可再設背景（`tests/floating-surface.test.mjs`）。

記住上次的頁面（ADR 0053，Windows 與 Android 相同）：`settings.json` 的 `lastPage`（`LastPageSettings`）記主頁面（曲庫、演出者、專輯、播放清單〔哪一份〕、播放佇列、設定〔哪個分頁〕）、開著的專輯／演出者明細（以身分鍵）與播放頁是否開著；不記捲動位置、搜尋文字、對話框。純函式在 `src/lib/start-page.js`（讀取、由狀態轉成儲存值、目標不存在時退回、發動意圖優先、防抖儲存），命令 `settings_get_last_page`／`settings_set_last_page`；Rust 與前端的頁面清單、分頁清單與預設值必須一致（`tests/start-page.test.mjs` 鎖定）。讀取寬鬆：缺欄位、損壞、未知頁面 id 或缺目標一律是曲庫，不報錯。導覽變更後防抖儲存，頁面隱藏、`pagehide` 與元件銷毀時立即寫出；還原完成前不儲存。啟動時最先讀取：不需查詢的頁面在載入曲庫之前就套用（不先閃出曲庫）；播放清單、專輯、演出者要等曲庫就緒後確認目標，目標已不存在就靜默停在曲庫，使用者已先切換頁面則不覆蓋。記住的播放頁在最早的時刻就整頁打開（不等播放快照、工作階段還原與封面；播放頁對沒有曲目是空狀態安全的，曲名、封面、歌詞在資料到達時補上），底下的頁面（含需查詢的目標）之後才換成記住的頁面，返回頁隨之更新；等候數秒仍沒有目前曲目才退回底下的頁面；使用者先關閉則不再處理。目標頁不存在時只退回曲庫，播放頁旗標保留。啟動時間線可在 localStorage 設 `moe.startTiming`＝`1` 後由主控台 `[start-timing]` 行讀取。啟動意圖優先：Windows 由檔案總管開啟音樂檔時不還原（`externalLaunch`）；Android 由別的 App 以「開啟方式」帶入音訊檔時同樣不還原（外掛有待取請求，見 `android-platform.md`、ADR 0054）。未驗證：Release／裝置上的實際還原（無曲庫閃現、真實資料的播放清單／專輯／演出者、播放頁立即開啟後的空狀態與補資料過程、Android 頁面隱藏後被終止）。

睡眠定時（ADR 0036）：播放頁頂欄「羅」與歌曲資訊（ⓘ）之間的鬧鐘按鈕開啟 `.floating-surface` 面板；小時、分鐘為兩個 `role="slider"` 欄位，各自夾住不進位（`adjustSleepTimerField`，上限 23:59，與 Rust `MAX_SLEEP_TIMER_MS` 同步），以手勢為單位凍結快照（`beginSleepTimerEdit`／`stepSleepTimerEdit`）。期限由 `src-tauri/src/sleep_timer.rs` 持有，到期送 `sleep-timer-changed` 並暫停（不是停止）；前端 `src/lib/sleep-timer.js` 只做顯示與換算。

專輯詳情捲動（ADR 0012）：曲目捲動視窗固定從「封面收合後的標題高度＋欄標題高度」開始，位置與大小不變；內容前有等於收合行程的空白，收合量恆為 `min(scrollTop, 收合行程)`（尺寸見 ADR 0012）。收合由單一進度變數 `--album-detail-collapse-progress`（0..1）驅動，兩個平台同一條路徑、不偵測功能：列表回報收合量，`AlbumDetail.svelte` 每個動畫幀最多寫一次到外殼（掛載、還原捲動位置、行程或標題高度改變、量測後立即寫），封面以左上角 `scale()`，摘要與欄標題 `translate()` 都讀它；不使用 CSS scroll timeline（Android WebView 會在慣性滑動時掉中間幀，ADR 0012）。例外（使用者核准）：封面旁摘要文字框的寬度與高度上限連續重排（`margin-left`、`max-height` 讀同一個進度變數，`contain` 隔離；演出者只顯示放得下的整行、超出以「…」結尾，統計恆顯示，不會碰到欄標題；摘要框高度恆等於其上限，演出者區塊頂端不動；整份演出者放得下（沒被裁）時摘要內容在固定高度框內垂直置中，被裁（填滿框）時靠上對齊，由 `fitArtists` 依裁切結果同一幀設定 `data-centered`（`summaryCentered`），邊界處內容最多移動半行；間距 5 px；見下一句）；演出者整行裁切（`album-artists-fit.js`，`AlbumDetail.svelte` 的 `fitArtists`）：Android WebView 的 `line-clamp` 不可用，改在 JS 以二分搜尋裁到剛好可用的整行並以「…」結尾（去掉結尾「．」與空白），不留半行、無漸層遮罩；文字可在任意字元斷行並兩端對齊（最後一行靠起點）；行高由首字 Range 實測、可用行數＝floor((摘要上限高度 − 統計高度 − 間距 + 0.5) ÷ 行高)（至少 1）、只用確定的輸入（不觀察摘要自身尺寸）並有遲滯（新行數須連續兩次算出且越過邊界才切換）；與進度變數寫入同一個動畫幀執行（另有掛載、尺寸改變、字型改變、演出者資料改變時），完整文字保存於 `artistsFull`，span 的文字只由該函式寫入；opt-in 量測 localStorage `moe.debug.albumReflow`＝1（`album-reflow-debug.js`，每秒一行「[album-reflow] …」）；Release 手機／平板實測待做（收合現在依賴主執行緒，尚待實機確認慣性滑動連續）。規則：封面／標題／排序表頭的收合只能動 `transform`，不得動畫 `width`、`height`、`top`、`flex-basis`，也不得每次 scroll 寫進度變數以外的樣式；不做逐列 clip-path、不攔截滾輪。改 transform 後尚未在真實 WebView2 搭配連續歌詞重驗。

專輯詳情資料（ADR 0037）：`AlbumDetail.svelte` 的 `loadDetailData` 讓 facets 與 artists 各自取得、不等封面；封面先用卡片的第一張，再背景換成拼貼。封面掃描規則（使用者定案，Windows 與 Android 相同）：只有使用者真的點進該專輯（含啟動時還原記住的詳情頁）才掃一次，`AlbumDetail.svelte` 在 `onMount` 啟動（`album-detail-cover-scan.js` 的 `createAlbumDetailCoverScan`），不跟著 `refreshKey` 或其他狀態重掃（`refreshKey` 只重載列表、快速索引與演出者）；不預掃、不背景掃其他專輯；每個呼叫（快速的 `representative: false`、完整的 `representative: true`、必要時 `forceRebuild`）對同一專輯項目只發一次，只走詳情專用命令 `album_detail_cover_ensure`；離開頁面（返回、換專輯、關閉）時 `onDestroy` 對用過的每個 key 呼叫 `album_detail_cover_cancel`，掃描立刻結束、不寫入任何結果、釋放資料庫連線。全域同時最多一個詳情掃描（`src-tauri/src/album_detail_scan.rs`：命令一到就登記，新登記會先取消前一個，前一個停止後才輪到下一個）。專輯首頁卡片的封面預載（`album_artwork_selection_ensure`）不受此規則限制。每次掃描在日誌印一行 `[art] album detail cover scan: N files, B bytes read, cancelled=…`（遠端另附向伺服器要了多少位元組）。已知取捨：掃描只在開啟時發生，開著詳情頁時改標籤換封面要重新進入才會更新。「依專輯曲目編號排序」：有碟號 ≥ 2 才分碟（`list_album_tracks_page_with_index_sort` 與 `album_detail_facets` 同一規則）。專輯頁點歌用 `PlaybackQueueSource` 的 `album` 來源、演出者頁用 `artist`、播放清單帶頁面 `sort`，佇列與畫面只有一個查詢與排序來源（Rust `queue_for_track`、`Database::list_album_track_ids`／`list_artist_track_ids`／`playlist_track_ids`，Windows 與 Android 相同）。測試 `album_queue_*`。

專輯首頁（ADR 0037）：卡片依 `trackListColumns.albumCardMaxWidthPx` 填滿整列（`album-index-layout.js` 的 `getAlbumCardGrid`）。封面預載目前視窗前後各一頁（`album-cover-prefetch.js` 的 `getAlbumPrefetchIndices`、`album-card-cover.ts` 的 `createAlbumCoverPrefetcher`），與卡片共用 `loadAlbumCardCover`；限流器 `withAlbumCoverLookupSlot`／`withAlbumArtworkSlot` 讓可見卡片永遠先於預載，避免大量第一次封面查詢佔住唯一的資料庫連線鎖。測試 `tests/album-cover-prefetch.test.mjs`、`tests/album-cover-lookup-slot.test.mjs`。診斷：命令 `db_slow_locks`（`player-db` 的 `TimedConnection`）。Release／手機捲動與多視窗寬度驗收待做。

列表（ADR 0037）：`PagedVirtualList` 列寬為 `max(100%, --track-list-min-width)`（`src/lib/grid-min-width.js`）；捲動視窗與 `AlbumIndex` 卡片格一律 `overscroll-behavior: none`，不可改回 `contain`。長按重排（播放佇列、設定「曲目欄位」）共用 `src/lib/long-press-reorder.js`（`longPressDragGuard`）。快速查找面板欄數由 `quick-index.js` 計算（寬度優先）。欄位標題首次點擊：時間類、長度、播放次數、音訊格式先降冪，其餘先升冪（`track-columns.js` 的 `getFirstSortDirection`）。列表文字省略（`MiddleEllipsis.svelte`，兩處共用 Windows／Android，省略符號固定為三個 ASCII 點，不用 CSS `text-overflow`）：所有儲存格共用 `ellipsis-fit.js` 的 `sharedFitter`——一個全 App 共用的 canvas 2D context（`font` 只在與上次不同時才設）、文字寬度快取（`font|文字`）與結果快取（`font|模式|寬度|文字`），皆為有上限的 LRU；全文寬度放得下時直接回傳原文、不搜尋；輸出與 `fitMiddleEllipsis`／`fitEndEllipsis` 逐字相同。儲存格不在每次換字時讀版面：可用寬度取自 `ResizeObserver`（`hostWidthFromResizeEntry`，四捨五入等同 `clientWidth`；呼叫端知道寬度時可傳 `maxWidth` 覆蓋），字型字串每個儲存格只讀一次 `getComputedStyle(host).font`，之後只在 `invalidateEllipsisFonts()`（介面字型變更、`document.fonts` 載入完成）時重讀。診斷：localStorage `moe.debug.ellipsis`＝`1` 時 `window.__moeEllipsisStats` 計數（measureText 次數、快取命中、字型／版面讀取），關閉時零成本。測試 `tests/ellipsis-fit.test.mjs`。未來最佳化：快速拖曳捲軸時虛擬列表可能短暫空白（候選做法見 ADR 0037）。

曲目欄位（ADR 0037）：十欄（標題、演出者、專輯、發行時間、新增時間、修改時間、長度、音訊格式、播放次數、來源）。預設可見度依平台（Windows 勾「新增時間」、Android 勾「修改時間」）：Rust `default_created_column_visible`／`default_modified_column_visible` 與前端 `defaultColumnVisible` 必須一致。「來源」本機為「本地」、遠端為伺服器名稱（`source_labels` 表、`TRACK_SOURCE_NAME_SQL`），預設隱藏；標題與內容置中（同數值欄）；欄寬由程式自動算成剛好完整顯示全部文字的最小寬度，不可手動調整、不存進 `trackListColumns.widths`（舊檔的值忽略，`widths.source` 只是相容佔位）：取「本地」加所有已設定伺服器名稱（不看畫面上的列）與標題「來源」加排序箭頭中最寬者，以清單真實字型量測（`src/lib/source-column-width.js`，`computeSourceColumnWidthPx`），來源增刪改名（設定頁載入帳號）或字型／字級改變時重算；各清單把 `$sourceColumnWidthPx` 傳進同一個 `trackListGridTemplate`／`trackListMinWidthPx`。所有 `TrackSummary` 由 `attach_file_names` 一併補上檔名、來源名稱與修改時間。曲庫預設依新增時間排序。

歌曲來源篩選開關（ADR 0037）：頂欄三段開關（`SourceScopeSwitch.svelte`、`source-scope.js`），只有同時有已啟用本地與遠端來源時顯示、播放佇列頁不顯示（`sourceScopeSwitchAppliesTo`），選擇存 `librarySourceScope`。範圍是查詢的明確參數、不是連線狀態：`player-db` 每個依畫面顯示的函式第一個參數是 `LibrarySourceScope`，`Database` 不保存範圍；SQL 佔位 `moe_in_scope(…)` 經 `LibrarySourceScope::bind` 換成純函式 `moe_source_in_scope`（未綁定即報錯）；命令以 `list_scope(state)` 讀 `settings.json`，Android 播放 actor 由 `SelectTrack` 帶入，不得再加任何連線層級的範圍。檔案內容與全部資料（匯出、同步、收藏改寫、備份、統計、播放解析、歌詞、指紋、session 還原、單曲摘要等）不帶範圍、永遠全部來源（分類見 ADR 0037）。切換範圍不動目前的播放佇列，佇列頁照原樣列出全部項目。**硬性規則：從任何列表建立的播放佇列必須正好是該列表頁面顯示的列與順序（範圍、搜尋、篩選、遺失檔案、停用來源都相同），佇列共用頁面查詢、不另寫 SQL；唯一例外是點的那首一定播放（列表已不顯示時放第一個）**（ADR 0037）。測試 `the_source_scope_*`、`every_list_queue_*`、`two_handles_on_one_file_*`、`export_keeps_cloud_entries_*`、`tests/source-scope.test.mjs`。

同步結果顯示（設定 → 音樂來源頂部橫幅）：每個來源一行「來源名　同步完成；新增 n 個項目，移除 n 個項目。」，有項目錯誤才加「，n 個項目錯誤」（`sync-result-line.js` 的 `formatSyncResultLine`，n 取自 `library-sync-finished` 的 `addedOrUpdated`／`removedMappings`）；進度條只在有已知總數的階段出現；只有失敗或沒有可同步來源時才顯示說明。

頻譜圖（ADR 0038）：獨立 Tauri 視窗（label `spectrogram`，`SpectrogramView`；Android 為全螢幕頁），可 A／B 比較（`src/lib/spectrogram-compare.js`），設定存 `moe.spectrogramSettings.v2`（`src/lib/spectrogram-settings.js`）。「Spek」配色是依其色階重新實作（`spek_color`），不得複製 Spek 的 GPL 程式碼；色階上限固定 0 dB。DSF／WVDSD 經 `player-tags` 的 `dsd_input` 轉 352.8 kHz 分析；DFF 與 Android 的 Opus 不支援。Release GUI 驗收待做。
