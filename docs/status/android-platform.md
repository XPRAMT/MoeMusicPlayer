# 現況：Android 平台

本文件是此領域「目前狀態」的快照，不是日誌；維護規則同根目錄 `AGENTS.md`「本文件維護規則」：就地改寫既有條目、不寫日期／量測數字／除錯經過，設計細節放 `docs/adr/`。

### Android 平台

建置與安裝：`npm run android:build:arm64`（debug、aarch64、`--apk --ci`，輸出 `release/moemusicplayer-android-arm64-debug.apk`）；日常小修改用 `npm run android:build:arm64:fast`（同一把金鑰，不做 LTO、不產 AAB，輸出 `release/moemusicplayer-android-arm64-fast.apk`，可直接覆蓋安裝）；使用者說「上傳 github」時才跑完整最佳化版 `npm run android:build:arm64:release`（`scripts/build-android-release.ps1`：fat LTO、單一編譯單元、strip、`opt-level=s`，同時產 APK 與 AAB，以 release 金鑰 `C:\APP\@Android\Play KEY.jks`〔別名 `anime theme key`，密碼由腳本從 `Play KEY.txt` 讀入建置程序環境變數〕簽章，找不到退回 debug 金鑰；版本碼為日期數字 26.10.19 → 261019；ADR 0023；換金鑰後舊 debug 簽章安裝須先解除安裝；release 版不可除錯，WebView CDP 驗收用 debug 版）。**每次安裝到有連線的裝置：手機 NX809J（`adb connect 192.168.1.10:5555`）與平板 23046RP50C（192.168.1.92，無線偵錯埠每次不同，先 `adb mdns services` 找埠再 `adb connect`／`adb -s <序號> install -r <apk>`）；連得上的都安裝並在上面測試驗收，連不上的就略過，結案報告註明哪台已安裝與測試、哪台略過**；任何裝置都不得重新啟動。**啟動 App 一律用 `adb -s <序號> shell am start -n com.moemusicplayer.app/.MainActivity`，不得用 `adb shell monkey`**：在手機 NX809J 上 monkey 會把系統的「自動旋轉」（`system accelerometer_rotation`）打開，之後畫面會隨手機姿勢橫直切換，座標點擊與截圖會對不上。用 adb 操作畫面前先確認方向，不在使用者手持操作時點擊。Android 專屬程式碼只在 aarch64-linux-android 目標編譯，變更共用 Rust 後須實際跑一次 APK 建置。

本機來源（ADR 0014、0039）：資料夾來源用 `AndroidFilesystem`／`fs_scan`；已有所有檔案存取權時改用 App 自己的資料夾瀏覽器（`android_folder_browser::pick_directory`、`FolderBrowserDialog.svelte`），因為系統選擇器不允許選儲存空間根目錄。排除資料夾存在 `excluded_folders`（與 Windows 同欄）。舊 `AndroidMediaStore`／`AndroidSaf` 來源不自動轉換。手機實測待做：資料夾瀏覽器、「在資料夾中開啟」、排除資料夾、本機歌詞候選、APK 更新。

播放服務與通知（ADR 0006、0039）：播放在外掛的 Media3 `PlaybackService`，佇列在 Rust；音訊生命週期不得依賴 Activity 存活，`MainActivity.onStart` 每次回前景 `ensurePlaybackService`；`onCreate` 必須 `addSession(session)` 才有 MediaStyle 通知。回前景畫面只剩底色的修正在 `MainActivity.onWindowFocusChanged(true)`（WebView `onPause`＋`onResume`）；再出現時的追查方式見 ADR 0039。

播放裝置（ADR 0044）：設定 → 播放頁分「模式」「裝置」「藍牙」（僅 Android）「DSD」四區（Windows 的「DSEE HX」在「裝置」與「DSD」間），Android 的裝置區（卡片上方的系統取樣率列含「前往授權」鈕，缺授權時才顯示）為 `AndroidOutputDevicesSettings.svelte`（`android-output-devices.js`），單選「系統預設」或一台裝置，存 `settings.json` 的 `androidOutputDevice`（null＝系統預設）；身分只看種類＋產品名稱（藍牙另加位址），規則只在 Kotlin `AudioOutputRules`。由播放服務套用、不依賴頁面：Rust `android_output` 保存選擇，`PlaybackService` 以 JNI `nativeOutputDevicePreference` 讀取，`AudioOutputRouter` 以 `AudioDeviceCallback` 呼叫 `setPreferredAudioDevice`（拔除改由系統預設、接上自動釘回）。列的格式與 Windows 清單相同（共用 `output-format.js`）：未在播放的列列出 `AudioDeviceInfo` 宣告的取樣率與聲道；播放中的列（選中的裝置，未選時為「系統預設」，副標「目前是：…」）為一行路徑（`describeAndroidPath`；路由到別的身分才警告；`LiveTrackOutput` 計數，晚到的舊軌釋放不得清掉新軌）「AudioTrack 取樣率 → 混音器取樣率（系統） → 編碼取樣率（編碼）．N 聲道」：混音器取樣率（`output.mixerSampleRate`，來源 `output.mixerRateSource`）：有 root（按過「檢查 root」後才探測 `su`）或已授權 Shizuku 時，`MixerRateLookup` 以 dump 讀該軌執行緒實際值，否則為 `getNativeOutputSampleRate` 串流值，讀不到就省略該步、不得推測；dump 安全規則見 ADR 0048（隱藏開關 `androidRealMixerRate`）；藍牙一律以編碼步結尾，LDAC 另標模式（「LDAC 990／660／330 kbps」「LDAC 自適應」，0＝「LDAC 預設」），只在有 root／已授權 Shizuku 時由 helper 的 `state` 讀 `codecSpecific1`（`BluetoothLdacModeReader`），否則只顯示「LDAC」、不猜（ADR 0051）；廣播不是 sticky，有 root／已授權 Shizuku 時編碼不明會經 helper 的 `state` 主動讀取（`BluetoothCodecStatusReader`：服務啟動時已有 A2DP 路由、每次載入曲目、輸出頁顯示、連線或路由變更、變更沒被確認時；失敗以 0.5／1／2／4 秒退避重試，執行器本身的錯誤不計入斷路器），沒有來源就維持「（藍牙）」、不由混音取樣率推測；不得稱 bit-perfect。藍牙編碼只來自藍牙堆疊的編碼廣播（`BluetoothCodecWatch`、`BluetoothCodecRules`；不得用隱藏 API），需 Android 13+ 與 BLUETOOTH_CONNECT，廣播不是 sticky；「附近的裝置」依 ADR 0039（說明面板）。輸出模式與 USB 獨佔（ADR 0047）：「共享」「獨佔優先」兩鈕，模式即 `androidUsbExclusive`（true＝獨佔，預設共享），獨佔下路由表選定的 USB 裝置已接上卻未授權時，服務自行請求系統 USB 權限對話框（`UsbPermissionAsk`；只在前景，拒絕後重接前不再問）。路由表（Kotlin `UsbExclusiveRules.route`）：獨佔下選系統預設或 USB 裝置 → 獨佔 USB 音訊裝置，其他裝置、沒有或拔除 USB → 共享；模式、選擇、USB 接上／拔除與取得權限都經 `PlaybackService.applyRoute`（`outputChange`）立即套用到播放中的歌。路由為獨佔、已授權且描述元支援該格式時，`UsbAudioOutputProvider` 給 Media3 一個 `UsbAudioOutput`（見 ADR 0047）；否則走 AudioTrack，列上註明原因，下一首重試。音量在 Rust 以增益套用，只有 100% 才位元完美；列以共用格式顯示（`describeAndroidExclusive`），顯示在獨佔使用的 USB 卡片，選系統預設時其「目前是」指出該裝置（`exclusiveTargetDevice`）；DSD 直通的列見「格式與解碼」。藍牙取樣率跟隨（「藍牙」區，ADR 0051，預設關，`androidBluetoothRateFollow`；沒有 root／已授權 Shizuku 時開關旁只顯示提示）：換歌時（`metadata.sampleRate`）若走 A2DP 且為共享模式（不含 USB 獨佔與 DSD），經 root／Shizuku 以 `app_process` 啟動 `BluetoothRateHelper` 呼叫 `setCodecConfigPreference` 只改取樣率，改為編碼支援的最近值（`BluetoothRateRules.pickRate`）；開關打開時立即套用目前曲目，失敗保持原狀；關閉、斷線、服務結束時盡力還原；見 ADR 0051。藍牙編碼優先順序（ADR 0052，開關 `androidBluetoothCodecCustom` 預設關，全部耳機共用順序 `androidBluetoothCodecOrder`）：清單列出本機可編的編碼（無資料時顯示「連接藍牙耳機後可選擇編碼」），沿用「曲目欄位」的長按拖曳；開關關閉時只記住順序，打開時立即套用，並在連線與調整順序時經 root／Shizuku 的 `BluetoothRateHelper` 切到耳機支援的第一個編碼，關閉時盡力還原；缺授權時「藍牙」區只有一則提示與一個「前往授權」鈕（共用面板，ADR 0048）。Android 不提供方案、音量同步、裝置音量／延遲、聲道映射、多裝置與 DSEE HX。待實機驗收：USB DAC／藍牙的釘住與自動釘回、編碼廣播數值、LDAC 模式讀取、Android 13 以下的系統路由、藍牙取樣率跟隨、藍牙編碼優先順序、USB 獨佔（SELinux、各格式、交還與重建、爆音）。

系統列安全區：貼邊內容四邊都用 `--android-safe-*`（`AndroidInsetsPolicy`→`moe:android-insets`→`.app-shell` 內距；fixed 元件與 JS 夾限用 `readSafeInsets()`），規則見 `src/lib/AGENTS.md`。待實機驗收：Android 9 橫向三鍵導覽（側邊導覽列）下的快速設定抽屜。

權限說明面板（ADR 0039）：所有檔案存取權、系統桌布需要的 `READ_MEDIA_IMAGES`、Android 17 的 `ACCESS_LOCAL_NETWORK`（targetSdk 37）都先顯示說明面板，按「前往授權」才請求；區域網路被拒時不呼叫遠端 IPC。API 37 系統提示的實機驗收待具備該版本的裝置。多個 SMB App 同時連不上時，NAS 445 埠、防火牆、Wi-Fi／VLAN 隔離也要列入調查。
