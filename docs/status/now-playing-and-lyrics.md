# 現況：播放頁、歌詞資料、播放時鐘與跳轉

本文件是此領域「目前狀態」的快照，不是日誌；維護規則同根目錄 `AGENTS.md`「本文件維護規則」：就地改寫既有條目、不寫日期／量測數字／除錯經過，設計細節放 `docs/adr/`。

### 播放頁與歌詞

歌詞設定三分頁（播放頁〔分頁 id 仍為 `general`〕／工作列歌詞〔僅 Windows〕／浮動歌詞，最後分頁存 `settings.json` 的 `uiPreferences.lyricsSettingsTab`）都經 `src/lib/LyricsLookSettings.svelte` 畫出同樣分組：「顯示」（啟用 → 顯示譯文 → 該頁專屬開關 → 動畫）、「字體與大小」（字型 → 字體大小 → 譯文大小（相對原文） → 字體粗細 → 句間距）、「文字效果」（群組內的文字效果選擇器不顯示小標、只有 aria-label → 自訂顏色 → 主要透明度 → 次要透明度 → 對齊／文字排版；三頁各自儲存自己的一組 `mainOpacityPercent` 1–100 預設 100、`secondaryOpacityPercent` 1–100 預設 50，播放頁存在 `lyricsPreferences`，舊的 `opacityPercent`／`inactiveOpacityPercent` 直接忽略不換算）、「位置與面板」；專屬設定以 snippet 放入對應分組，標題用 `.quick-settings-group h3`；前端純函式在 `src/lib/floating-lyrics-settings.js`。一般頁譯文與羅馬拼音大小是相對原文百分比 `lyricsPreferences.auxiliaryScalePercent`（1–100，預設 90），舊檔的 `auxiliaryFontSizePx` 由 Rust（`RawLyricsPreferences`）與 `normalizeLyricsPreferences` 換算為 round(譯文 px ÷ 原文 px × 100) 並不再寫回；播放頁以 `lyricsAuxiliaryFontSizePx` 繪製。字體大小 1–50 px，舊設定檔的 0 載入為 1。字體粗細 `fontWeight`（100–1000、滑桿步進 100、預設 500）三分頁各自儲存，缺欄位為 500、載入時夾值；它是原文的字重，譯文與羅馬拼音恆為字重 −50（至少 1）；播放頁以 `--lyric-primary-weight`／`--lyric-auxiliary-weight` 繪製，Windows 原生為 DirectWrite 字重（1000 以 999 繪製），Android 為 `Typeface.create(…, weight, false)`（API 28 以上；更舊的系統字重 ≥ 600 為粗體），非可變字型會對應到最近的可用字重（見 ADR 0041 5.5）。

歌詞只有一份：`App.svelte` 的歌詞控制器載入一次（播放頁開過或歌詞視窗啟用時才跑），播放頁 `LyricsView` 以 `sharedController`／`sharedState` 顯示，同一份（已套用後端繁體行、只含同步行、附偏移）經 `taskbar-lyrics-data`（`src/lib/taskbar-lyrics-data.js`）推給歌詞視窗；歌詞視窗不搜尋、不載入、不轉換。偏移計算只有 `lyrics-timing-offset.js` 的 `lyricsDisplayOffsetMs(lyrics.offsetMs, 每首延遲秒)`；每首延遲存曲庫資料庫（`track_lyrics_timing_offsets`，以 Track ID 為鍵、單位 0.1 秒，Windows 與 Android 同一份 Rust；`lyrics_timing_offset_get`／`lyrics_timing_offset_set`，寫入依序進行），調整時 `emit('lyrics-timing-offset-changed', { trackId, delaySec })`，App 轉成 `lyrics-native-delay`（Android 為 `floatingLyricsUpdate`）。歌詞視窗沒有換行提前，在 `startMs - offset` 換行。

播放頁同步歌詞（ADR 0029）：虛擬視窗依捲動位置繪製（`lyrics-window.js` 的 `getTimedLyricWindow`、`sameLyricWindow`）。換行動畫提前開始、在該句時間點剛好結束，提前量只定義在 `src/lib/lyrics-cue-timing.ts` 的 `LYRIC_CUE_LEAD_MS`（不開放設定）；`activeTimedIndex`（`data-current-cue-index`）是真正的當前句，畫面用 `displayTimedIndex`（`data-active-cue-index`）。所有捲動變化經 `lyrics-scroll-glide.ts` 的 `planTimedScroll`；跳轉、換歌、版面改變與 `prefers-reduced-motion` 一律 instant。瀏覽並跳轉（`lyrics-browse.js`，見 ADR 0029）：使用者捲動同步歌詞即進入瀏覽，視窗中心那句（不是目前句時）在常駐的左右對稱留白 `--lyric-browse-gutter` 內顯示播放鈕 `.lyric-browse-seek`（不壓字、出現時不重排；跳轉點達到或超過曲長的句不顯示），點擊經 `onSeek`（`commitPlaybackSeek` → `seekPlayback`）跳到該句成為目前句的時間（`browseSeekPositionMs`，不含提前量）並結束瀏覽；捲動結束後 `BROWSE_HOLD_MS` 內換行不拉回，之後第一次換行才回到目前句（`browseHoldAfterScroll`、`browseCueAction`），跳轉與換歌立即回到目前句；純歌詞與歌詞視窗沒有此功能。播放次數、上一首 3 秒判斷用原始時間。測試：`tests/lyrics-browse.test.mjs`、`tests/lyrics-cue-timing.test.mjs`、`tests/lyrics-scroll-glide.test.mjs`、`tests/lyrics-controller.test.mjs`、`tests/lyrics-view.playwright.js`（需另開測試伺服器）。

播放進度時鐘（ADR 0028）：主視窗每 500 ms 取播放快照（`App.svelte` 的 `PLAYBACK_POLL_MS`，最小化時照跑），之間由 `src/lib/playback-clock.ts` 推算並平滑校正，大偏差、換歌或狀態改變時跳轉（`jumpId` +1）。卡住（後端仍回報播放但位置不動，例如遠端串流等資料）時時鐘不得往回跳：凍結在畫面位置（`frozen`，`playbackClockRunning` 為 false、`msUntilPlaybackPosition` 回傳 null，`runKey` +1、不動 `jumpId`），真實位置追上或恢復前進且差距夠小才從凍結位置繼續；判定門檻（`STALL_*`）見 ADR 0028。原生歌詞視窗跟隨音訊引擎時鐘，不用此時鐘。進度條是只動畫 `transform` 的 linear Web Animation（`src/lib/progress-run.js` 的 `use:progressRun`：`.progress-band` 光暈平移、`.progress-thumb-mover` 圓點平移，跑在合成器上，每幀不得有樣式重算或排版；不得改回動畫 `@property`、`left`、`width` 或漸層停點），只在 `jumpId`／狀態／`runKey` 改變或拖動結束時重設（`PlaybackProgress.svelte`，凍結時停在該比例），不逐幀更新。底欄「邊緣」時間軸（`data-timeline-style="edge"`）是 `.app-shell` 內容區與底欄之間獨立的一列（`--dock-timeline-band`＝`--dock-edge-progress-track` 3 px，其他樣式為 0），內容區止於此帶頂端，時間軸的繪製與點擊都不得進入內容區；點擊範圍＝此帶＋向下伸入底欄 `--dock-edge-progress-hit-below`（10 px），時間文字在底欄頂端下 `--dock-edge-progress-label-top`（`tests/dock-timeline-band.test.mjs`，見 ADR 0028）。緩衝提示（使用者核准）：快照為 `buffering` 時輪詢暫時改為每 100 ms（同一個輪詢計時器換間隔，`playbackPollIntervalMs`，狀態一改即回 500 ms；緩衝樣本不算 playing，不影響停滯判斷），連續緩衝滿 1 秒（自第一次看到起算，單一計時器、狀態改變即取消）才開始脈動：圓點 `.progress-thumb` 以 CSS `filter: brightness()` 1→0.8→1 每 1000 ms 一週期；緩衝結束後播完目前這一圈才停（只在 `animationiteration` 週期邊界判斷，最後一圈中再緩衝就接著繼續；`buffering-cue.js`），這是唯一提示（不改文字、aria 或 tooltip），減少動態時不脈動，見 ADR 0028。需要即時位置處用 `currentPlaybackPositionMs()`。後端事件推送尚未做。測試 `tests/playback-clock.test.mjs`。

跳轉與焦點：前端所有 `playback_seek` 只能經 `src/lib/ipc.ts` 的 `seekPlayback(positionMs, durationMs?)`（`seek-position.js` 的 `normalizeSeekPositionMs` 四捨五入為整數毫秒並夾在 0..曲長；Rust 維持 `u64` 契約；`tests/seek-position.test.mjs` 檢查無其他直接呼叫）；Rust `playback_seek` 再夾一次；跳到結尾（快照回報的曲長）或之後、或在檔案尾端解碼器無法 seek，一律當成曲目自然結束（`player-core` 的 `seek.rs`；Windows／Android 的 `end_track_by_seek`），絕不變成錯誤或停止：播放中下一首照常播放，暫停中走訪到的下一首停在開頭維持暫停，都開始不了就停在結尾；其他位置的 seek 失敗照舊（見 ADR 0036）。`shortcutEventShouldRun` 對 `shortcutTargetIsSeekBar` 一律放行；未綁定的方向鍵／PageUp／PageDown 由 `handleSeekKeydown` 依 `playbackSeekKeyStepMs`（±5 s／±30 s）從播放時鐘跳轉，按住重複只 `preventDefault`；Home／End 保持原生；音量條等其他滑桿照原生。點擊不留焦點（全 App 規則）：`src/main.ts` 呼叫一次 `installPointerFocusRelease(document)`（`src/lib/pointer-focus.js`）：滑鼠／觸控按下按鈕、range、checkbox／radio（含對應 role）後，pointerup 之後的下一個 task 移除焦點；`select` 於 `change` 後移除；文字欄位不套用；點擊處理已移走焦點就不動；modal 內焦點交給 modal 容器；鍵盤取得的焦點不處理，外框用 `:focus:not(:focus-visible)`。新控制項不需另外處理。

播放鍵與 seek 期間（ADR 0036）：Android 緩衝中回報 `"buffering"`（`PlaybackService.kt` 的 `playbackStateName`、Rust `android_playback.rs` 的 `counts_as_playing`），播放鍵不閃成暫停，收聽計時與播放時鐘只在 `playing` 前進。seek 走 `sendPlaybackCommand(..., { seek: true })`（`isSeeking`），忙碌時忽略點擊但外觀不變；上一首／下一首不因指令忙碌反灰。從任何清單選曲不受忙碌旗標限制，最新選擇勝出，被取代的指令結果與錯誤一律忽略（`playback-command-order.js`）；後端同樣：Android 播放 actor 與 `PlaybackService` 的輪詢、Windows 音訊 worker（`LoadCounter`、`PrefetchReader::with_cancel`）都讓新選的曲目取代仍在等伺服器的載入（ADR 0026、0036）。換曲先備妥再切換（ADR 0036，Windows 與 Android 相同）：任何會開始另一首的操作（點曲目、各種播放、上一首／下一首、曲目自然結束）都先把新檔案開啟並驗證，成功才切換；準備期間目前的音樂照常播放，狀態、播放列、佇列游標、位置與收聽時間不變，游標、目前曲目、session 與播放次數只在成功時改變。手動開始只試一次，失敗什麼都不改並顯示自動消失的通知（連不上伺服器＝「伺服器無法連線」，其他＝「無法播放這首歌」，`start-failure-notice.js`），不自動跳下一首；自然結束則依佇列順序逐首嘗試、失敗不中止（`player-core` 的 `track_start.rs`：單曲循環只重試同一首、全部循環繞一圈每首最多一次、不循環到最後一首為止；連不上的伺服器本輪其餘曲目略過，但整首都在磁碟快取的曲目不算該伺服器的〔`walk_server_key`〕、不被略過），都失敗就停在結尾並通知，使用者任何新選擇結束走訪。後端以快照 `startFailure`（`kind`、遞增 `sequence`）把失敗帶給前端。Windows：遠端檔案由 `moe-audio-probe` 輔助執行緒檢查（`AudioBackend::probe`），走訪在 `advance_ended_queue`；Android：`MediaPreflight` 在動 ExoPlayer 之前開檔並辨識容器，拒絕時 ack 帶 `retained`，走訪在 `start_after_natural_end`。測試：`tests/seek-transport-lock.test.mjs`、`tests/start-failure-notice.test.mjs`、`PlaybackProtocolStateTest`（`gradlew :tauri-plugin-media-index:testDebugUnitTest`）、`android_playback::integration_tests`、`windows_library_integration_tests`。待實機驗收：Windows 真實遠端伺服器。

播放頁切歌封面：大封面用 `nowPlayingArtworkObjectUrl`（`src/lib/active-track-artwork.ts`）：`ready`，或新封面 `loading` 而控制器保留上一首 object URL 時繼續顯示舊圖並維持有封面版面；新封面 `decode()`（`createDecodedImageObjectUrl`）後才替換；`missing`、過大或失敗才隱藏、歌詞置中；generation 序號丟棄舊結果。底欄小封面不受影響。測試 `tests/active-track-artwork.test.mjs`。專輯首頁卡片封面、專輯詳情封面及底欄封面皆直角；底欄封面在所有頁面使用同一個全域樣式。

正在播放封面縮放（ADR 0036，`src/lib/cover-zoom.js` 的 `coverZoom`、去除 swipe 回饋的幾何 `src/lib/cover-swipe-feedback.js`、重光柵規則 `src/lib/cover-reraster.js`，`tests/cover-zoom.test.mjs`、`tests/lyrics-layout-freeze.test.mjs`）：滾輪或雙指縮放、雙擊還原（滑回）、放大後可平移；只對封面套 transform，版面依倍率預留欄寬並即時擠壓歌詞區；所有輸入合併為每幀一次 rAF 套用；縮放期間歌詞文字版面凍結（`layoutFrozen`），輸入停止 `COVER_ZOOM_SETTLE_MS` 後一次重排並置中，列以行索引為 key 就地更新、不重建。縮放中的封面以 `data-cover-zoomed` 屬性標記（不用 class，只改版面）。圖層結構固定（硬性規則）：`.now-playing-view .cover-stage` 永久 `z-index: 1`＋`will-change: transform`，手勢或動畫開始／結束不得切換 `will-change`、`z-index`、`contain`、`isolation`、`position` 等合成／堆疊屬性（Android 會整片重新點陣化而空白）。清晰度由「重光柵微移」負責（`src/lib/cover-reraster.js`，ADR 0036「封面清晰度」）：放大（倍率 > 1）且穩定 `COVER_LAYER_IDLE_MS`、沒有手勢或 swipe 回饋時，對 stage 做一次 inline `translate: 0.01px 0px`（transition none）再於下一幀改為 `translate 180ms` 清掉，約 260 ms 後還原原 transition；倍率每次變化穩定後再做一次，倍率 ≤ 1 不做，換歌新圖載入後再做；手勢開始取消微移，swipe 回饋蓋過它時以回饋為準、只收回自己寫的屬性；殘留指標規則：`pointers` 非空即視為手勢中，所以滑鼠條目在 window 捕獲階段的 `pointerup`／`pointercancel` 或 `buttons === 0` 的 `pointermove` 時一律移除（只限滑鼠，觸控／筆不受影響；`src/lib/cover-pointers.js`，ADR 0036）；沒有任何覆蓋 canvas（ADR 0036「還原動畫跑在 stage 上」）：雙擊還原（放大或縮小皆同）由 stage 自己跑 Web Animation（`restoreGlide`：反向 transform → identity、`COVER_RESET_MS` 200 ms、`ease`、`fill: none`），結束或被取消後 stage 的 transform 就是真正的最終狀態；動畫中再有滾輪、手指按下就取消動畫並從已到達的畫面接手（`interruptGlide`／`stateFromVisual`，沒有跳動）；`swipeDismiss` 的回饋只作用在 stage，幾何讀取一律去除回饋（`stageRect`／`withoutSwipeFeedback`）；除錯：`localStorage['moe.debug.coverSwipe']='1'` 在每次微移記錄 `[cover-reraster]`。版面變動與補償 transform 必須在同一幀、繪製之前完成（FLIP：每步縮放 `settleLayout` 後 `repin()`；還原先提交最終版面再以 `flipTransform` 求反向 transform），不得有未補償的一幀。倍率範圍、時間常數、理由見 ADR 0036。直排／橫排只看長寬比例（`@media (orientation: portrait)`）。縮小的封面切歌後維持、放大的切歌即還原（`coverZoomPersisted`）；跨重啟只記縮小（`settings.json` 的 `coverZoom.scale`，`settings_get/set_cover_zoom`）。修復經過與驗證方式見 `docs/lessons/cover-zoom.md`。

手勢（ADR 0036）：`src/lib/swipe-dismiss.js`（`use:swipeDismiss`，`tests/swipe-dismiss.test.mjs`）。窄版導覽面板左滑 → `closeNavPanel`，快速設定右滑 → `closeQuickSettings`；正在播放封面與歌詞區左滑（deltaX < 0）→ 下一首、右滑 → 上一首（使用者實測確認，勿對調），封面下滑 → `closeNowPlaying`；滑鼠（`mouseActions`）在 `.now-playing-view` 水平拖曳切歌、`.cover-stage` 向下拖曳收合；只有放大時（`data-cover-pannable`）滑鼠拖曳是平移，縮小或倍率 1 時照常切歌與收合（`data-cover-zoomed` 只管版面）。從 input／select／textarea／`[role="slider"]`／`[data-swipe-ignore]` 開始的手勢一律忽略。

線上歌詞自動套用（`player-core` `auto_lyric_candidate`）：候選須同時通過標題相似度門檻（`AUTO_MATCH_TITLE_MIN_SIMILARITY`）、時長差門檻（`AUTO_MATCH_MAX_DURATION_DIFF_MS`，任一方未知即不合格）且為同步歌詞；加權分數只用於在合格者中排序（門檻與權重見 ADR 0041 5.6）。手動選擇永遠優先。線上搜尋時，每批前幾筆 QQ 命中另向 AMLL TTML DB（CC0）要 `qq-lyrics/<mid>.qrc`（`fetch_amll_qq_qrc`，有大小與逾時上限，失敗靜默，見 ADR 0041 D6），有逐字就多一個候選 `qqmusic-amll:<mid>`（`parse_qrc`，譯文與羅馬音借自同 mid 的 QQ 候選），同分排在行級 QQ 之前；只在使用者搜尋時連線，不內建歌詞、不解密 QQ 加密 QRC（ADR 0041 D6）。

本機歌詞（ADR 0040、0041）：沒有手動選擇時依「內嵌 → 旁檔（`.lrc` > `.qrc` > `.ass` > `.srt`）→ 線上」，所有平台相同，每次都讀檔案當下內容（資料庫只記旁檔在哪，見「曲庫同步與資料」）；內容以 `parse_any_lyrics` 依內容判斷（LRC／yrc／明文 QRC／SRT／ASS／純文字；單一十六進位或 Base64 區塊是加密 QRC，不解密，視同沒有），看似字幕卻解析不出的（`Unusable`）視同沒有。選「同名 LRC」`local:sidecar` 或「內嵌歌詞」`local:embedded` 時手動列只存來源參照、每次讀當下內容；線上手動選擇仍用存下的文字。「不再搜尋」只表示這首歌不再自動線上搜尋（`cleared:` 空白手動列，ADR 0041 D1）：每次載入照樣讀內嵌與旁檔、有就照常顯示，都沒有才不顯示且不自動搜尋；手動搜尋與選擇照常。候選清單的本機項目也讀當下內容、內嵌在前。LRC 同時間戳行、SRT 多行／成對 cue、ASS 同時間事件的額外行依內容分成譯文或羅馬音（`lyric_roles.rs`，規則見 ADR 0041 D9），播放頁順序為原文 → 羅馬音 → 譯文。播放頁目前行有逐字，或沒有逐字但有自己的結束時間（`endMs`，當成一個從起點到結束、涵蓋整行的字，`karaokeWordsOf`；兩者皆無的行不掃）時，以卡拉 OK 方式呈現：整行只有一條 `var(--accent)` 邊界沿 `karaoke_glide` 由左到右掃過、已唱的部分維持主色到換行、未唱的白色（單一 CSS 動畫，`lyrics-word-highlight.js` 的 `karaokeLineAnimation`，做法見 ADR 0041 D8；減少動態時在每個字起點整字變色、不掃）；譯文行沒有逐字效果，羅馬音只有帶 `romanizationWords` 時才有；工作列與浮動歌詞的逐字見「歌詞視窗」。「導入使用中歌詞」（`lyricsToText`）把有結束時間但沒有逐字的行寫成 `[起點]<起點>文字<結束>`，結束時間因此保留。

簡繁轉換（ADR 0030）全專案只有一份：`crates/player-zh`，OpenCC 上游 ver.1.4.2 原檔放在 `crates/player-zh/data/opencc-1.4.2/`（`SOURCE.md` 記版本與 SHA-256，`.gitattributes` 設 `-text`），`include_str!` 內嵌。只換字形不換用詞：`to_traditional`＝STPhrases＋STCharacters（含 keep-只 覆寫）→ TWVariantsPhrases＋TWVariants；`to_simplified`＝TWVariantsRevPhrases＋TWVariantsRev → TSPhrases＋TSCharacters；含日文假名的整行或欄位不轉。使用者規則：簡體「只」一律不轉「隻」（由 STPhrases 推導覆寫表還原）。用途：歌詞顯示（`LyricLineDto` 的 `textTraditional`／`translationTraditional`，前端 `lyricsForDisplay` 同步挑選）；線上歌詞一律只用簡體搜（`lyrics_search` 自行轉簡，前端不送 `queryAlternates`）；曲庫搜尋由 player-db `search_terms_json` 加 `search_alternates`；身份鍵 `music_identity_key` 用 `to_traditional`（只在每連線的 TEMP 表）；候選評分 `fold_to_simplified`。`opencc-js` 只剩 devDependency（`scripts/i18n-catalog.mjs` 的 twp→cn、`scripts/generate-zh-convert-fixture.mjs` 重產 `tests/fixtures/zh-convert-opencc-js.json`；差異只能是 `tests/fixtures/zh-convert-differences.json` 記錄的項目）。前端不得再引入任何簡繁轉換。
