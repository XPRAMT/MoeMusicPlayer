# 現況：歌詞視窗（工作列歌詞、浮動歌詞）與動畫規則

本文件是此領域「目前狀態」的快照，不是日誌；維護規則同根目錄 `AGENTS.md`「本文件維護規則」：就地改寫既有條目、不寫日期／量測數字／除錯經過，設計細節放 `docs/adr/`。

### 歌詞視窗（工作列歌詞、浮動歌詞）

原生繪製（ADR 0034）：Windows 工作列歌詞與浮動歌詞由 `crates/player-lyrics-native` 繪製（Windows.UI.Composition＋D2D／DWrite，單一 `moe-lyrics-native` 執行緒；`plan.rs`、`sampling.rs`、`win.rs`、`shared_cache.rs`），沒有 WebView 歌詞視窗；需要 Windows 10 1809 以上，更舊的系統不建立歌詞視窗。每行點陣化一次並跨視窗共用（點陣鍵含各列字重與字型家族），每個合成幀只提交有變的值，閒置時不輪詢；播放時鐘取自音訊引擎（`position_at`）。規則在 `crates/player-lyrics-rules`（參考實作），由它產生共用向量 `tests/fixtures/lyrics-rules-vectors.json`（`cargo run -p player-lyrics-rules --example generate_vectors` 重產，`shared_vectors.rs` 檢查提交的檔案與產生器輸出相同）；Kotlin（`FloatingLyricsRules.kt`、`WordLyricsRules.kt`）與主視窗仍在執行的 JS（選句、偏移、長句捲動、播放頁卡拉 OK 的 `lyrics-glide.js`）都對照它，連續捲動條沒有 JS 版本。逐字歌詞（ADR 0041 D10，Windows 原生與 Android 浮動歌詞；曲線在 `player-lyrics-rules` 的 `glide.rs`、Kotlin `WordLyricsRules`，共用向量）：連續模式不看個別字的時間，每一行各自判斷有沒有逐字；逐字行以行起點與最後一個字的結束為節點，與其他行的起點節點接成一條單調 C1 曲線（`word_strip_knots(lines, final_arrival_ms)`＋`knot_cubic`，與行級 `strip_cubic` 同一族）；結束節點逐行決定、不看檔案格式（`knot_line_ends`／Kotlin `knotLineEnds`）：有逐字 → 最後一個字的結束，否則有行自己的結束時間（`endMs`：SRT／ASS cue、yrc／QRC 行長、增強型 LRC 收尾時間戳，經 `taskbar-lyrics-data`／`floatingLyricsUpdate` 傳入，偏移與起點相同）→ 該時間，否則（最後一行除外）在下一行起點晚於「起點＋長度上限」時以上限為結束節點（`line_cap_ms`，`KnotLine.cap_ms`）；最後一行沒有逐字時用自己的結束時間，沒有才用末句終點估計（`final_arrival_with_end_ms`、`terminal_line_estimate_ms`，不超過曲目結尾）；上限與估計都依 East Asian Width 分寬窄字形叢集（W／F 表由 `scripts/generate-east-asian-width.mjs` 產生 Rust／Kotlin 兩份，`tests/east-asian-width.test.mjs` 檢查相同）；整首沒有逐字的歌也走同一條節點路徑；數值與節點取捨規則見 ADR 0041 D10。譯文跟著主列。「無」模式為卡拉 OK：自己帶逐字的行，以及沒有逐字但有自己結束時間的行（當成一個涵蓋整行的字，`whole_line_word`／Kotlin `wholeLineWord`，Windows `LyricLine::karaoke_words`）才有邊界，兩者皆無的行不掃，每行一條，沿 `karaoke_glide`（`smooth_glide`）由左到右；Windows 為白色與主色兩張快取表面加互補裁切，Android 為 `clipRect`；曲線每行建一次、每幀只取值。資料流：主視窗廣播 `taskbar-lyrics-data`／`taskbar-lyrics-playback`／`lyrics-accent-color`／`lyrics-native-delay`／`floating-lyrics-tips`，`src-tauri/src/native_lyrics.rs` 接收，需要時以 `taskbar-lyrics-request`／`taskbar-lyrics-playback-request` 要求重送；WM_CLOSE 轉成主視窗正常關閉。診斷：`MOE_LYRICS_NATIVE_LOG`、`MOE_LYRICS_FRAME_LOG`、`MOE_LYRICS_NO_FADE`，`--example measure`／`--example demo`。待辦：使用者實機驗收（外觀、鎖頭 tooltip、固定模式穿透、拖曳存檔、自動隱藏／全螢幕／Explorer 重啟、熱插拔、DPI、裝置遺失重建）；歌詞開啟時其他執行緒額外 CPU 的來源待查。

工作列歌詞（ADR 0018、0031，僅 Windows，預設啟用）：設定 `settings.json` 的 `taskbarLyrics`（`settings_get/set_taskbar_lyrics`，Rust `TaskbarLyricsSettings`，前端 `taskbar-lyrics-settings.js`，變更經 `taskbar-lyrics-settings` 事件廣播）。`src-tauri/src/taskbar_lyrics.rs` 的監看執行緒為每條工作列（`taskbar::list_taskbars`）各建一個視窗、擁有者為該工作列，以 UI Automation 算空白處擺位（純函式 `free_stretches`／`pick_free_area`／`lyrics_area`）；自動隱藏、直式工作列、空白太窄、全螢幕／簡報時隱藏（`foreground_covers_monitor_of`）。`displayMode`：`all`（預設）／`playerMonitor`／`custom`（`customMonitors`，按鈕來自 `taskbar_lyrics_monitors`）。「暫停時隱藏」`hideWhenPaused`（預設開，工作列與浮動分開儲存）：暫停或停止時所有工作列視窗 200 ms 淡出（composition 不透明度動畫）並完全穿透、不再刷新或排幀，播放時淡入；換歌、緩衝、跳轉不隱藏（純函式 `pause_hide::PauseGate`，規則見 ADR 0034）。只顯示同步歌詞，過寬的行依播放位置水平捲動（`getLyricScrollProgress`）。診斷 `cargo run -p player-platform-windows --example probe_taskbar`。待驗收：第二螢幕位置與字級、「識別」編號是否與按鈕一致、熱插拔、Explorer 重啟、playerMonitor 切換、Win10 工作列。

浮動歌詞（ADR 0032；Windows 為原生置頂透明視窗，Android 為系統懸浮窗）：`settings.floatingLyrics`（`FloatingLyricsSettings`，外觀欄位同 `taskbarLyrics`，另有 `enabled` 預設關、`locked`、`position`、Android 專用的 `landscapePosition`），可與工作列歌詞同時開啟；「暫停時隱藏」同工作列歌詞（`floatingLyrics.hideWhenPaused`，隱藏時解鎖鈕也隱藏、不接收滑鼠／觸控）；Android 由 `PauseHide.kt` 判斷、視窗 alpha 200 ms 淡到 0（鎖定時淡回系統上限），淡出後渲染執行緒停止排幀（ADR 0032）。Windows `src-tauri/src/floating_lyrics.rs`（`settings_get/set_floating_lyrics`、`floating_lyrics_set_locked`、`floating_lyrics_reset_position`、`floating_lyrics_fit`、`floating_lyrics_nudge`、`floating_lyrics_centre_axis`）；只有歌詞區必須留在工作區內；固定模式整窗穿透，只有游標在解鎖按鈕上時接收滑鼠。`widthPx` 是**歌詞區**寬，面板＝左右透明邊＋歌詞區＋右側鎖頭欄；上方透明空間只由主行決定（顯示譯文不會讓第一行移動，譯文列掛在主行下方、只有下方空間隨整個歌詞區），儲存的位置是歌詞區左上角而非視窗左上角（Android `FloatingLyricsRules.windowOrigin／areaOrigin`，Windows `Gutters::window_from_area／area_from_window`；拖曳、十字鍵、置中、重設、移到狀態列、夾限、寬度與字級變更都經它們）。位置與鎖定兩平台都只存在 `settings.json`，單位是占螢幕的比例：x＝（歌詞區 x − 螢幕左緣）／螢幕寬，y 同理；螢幕在 Windows 是整個虛擬桌面（所有螢幕的外框，`floating_lyrics::virtual_desktop`），在 Android 是目前方向的顯示器；Android 的 `position` 是直向、`landscapePosition` 是橫向，沒有值＝置中。比例換回像素後一律夾限，只有歌詞區（含鎖頭欄）必須留在螢幕／工作區內；換算與夾限是 `player-lyrics-rules` 的 `placement`（`position_ratio`／`position_px`／`clamp_kept_box`／`restore_area_origin`，共用向量 `placementRatio`／`placementPx`／`placementClamp`／`placementRestore`；Kotlin `FloatingLyricsRules.positionRatio／positionPx／clampKeptBox／restoreAreaOrigin`，Windows 的 `place_on_monitors_with` 也走 `clamp_kept_box`），Android 新建視窗、旋轉與舊值搬移都走同一條還原路徑。`locked`、`position`、`landscapePosition` 只由各自的指令（Windows）或懸浮窗經 JNI 回報（Android）改變，`settings_set_floating_lyrics` 一律保留已存的值，不採用頁面送來的（兩平台）。設定檔以 `floatingLyrics.positionUnit`（`screenRatio`）標示單位；沒有這個欄位的舊檔，其 `position` 是虛擬桌面的整數像素，讀取時以當下虛擬桌面換算一次並寫回（Android 上捨棄）；`landscapePosition` 只對 Android 有意義，Windows 忽略。備份：zip 的 `manifest.json` 記錄平台、不同平台的 zip 拒絕匯入，所以位置不會跨平台；單獨匯入的 `settings.json` 沒有平台資訊，位置照原樣保留（還原時仍會夾限）。鎖頭圖示表示目前狀態（開鎖＝可移動、閉鎖＝鎖定）。設定頁「面板」：Android 獨有「移動到狀態列」是一次性移動（`centredOnBar`，依方向儲存），不是模式；十字鍵、水平置中／垂直置中／重設位置、寬度滑桿。Android：`FloatingLyricsOverlay.kt`，頁面經 `floating_lyrics_android` 送 `floatingLyricsUpdate`（指令協定不變）；鎖定與位置由 Rust `android_floating.rs` 持有副本（啟動時讀設定）並負責寫入 `settings.json`，Kotlin `FloatingLyricsStore` 經 JNI 讀取（Rust 尚未讀到設定時回 null：沿用記憶體中的值、之後再讀）並回報變更（立即更新副本，背景執行緒寫檔並送出 `floating-lyrics-settings`，不卡 Android 主執行緒）；舊版存在 SharedPreferences `moe_floating_lyrics` 的 `locked`、`x_／y_<方向>`（像素）由 `FloatingLyricsLegacyPrefs` 搬移一次（以當下該方向的螢幕換算比例，`settings.json` 已有的位置不覆寫，鎖定取舊值），Rust 寫入成功後才清除舊鍵，檔內只留除錯旗標 `trace` 與 `migrated`；懸浮窗權限只能由使用者在系統設定頁開啟（禁止 adb 授權）；未授權時浮動歌詞頁「顯示」最上方（「啟用」之前，`displayNotice` snippet，`floatingLyricsOverlayNoticeVisible`）顯示「顯示在其他應用程式上層」提示與「開啟系統設定」，已授權或尚未讀到狀態時不顯示，回到 App（`visibilitychange`／視窗 `focus`）重讀 `floatingLyricsStatus`。渲染（ADR 0032 “Android overlay rendering notes”、ADR 0034）：只有專用執行緒 `moe-lyrics-render` 以 OpenGL ES 2.0 繪進視窗內的 SurfaceView（`GlLyricsPanel`、`LyricsRenderThread`、`GlLyricsRenderer`；主執行緒只管視窗版面、鎖頭按鈕與觸控）；時鐘取自 `PlaybackService` 發布的 `ClockSnapshot`（`LyricsClock`），每幀參數由純函式 `RenderBuilder`＋`LyricsFramePlanner` 算出，行影像由 `RasterWorker` 在背景點陣化成分塊紋理；幀率由該執行緒的 Choreographer 跟隨顯示器目前的更新率，只在畫面有變時繪製。翻譯列在整首歌有譯文且開啟時整首固定預留（視窗高度固定）。視窗 alpha 恆為 1，只有鎖定且 Android 12+ 時為系統最大遮蔽不透明度，繪製值不補償。沒有備援也沒有渲染器開關（Views 路徑已刪除）：EGL 或渲染執行緒失敗時只記錄原因（tag `MoeMediaIndex`）、不顯示任何東西，關閉再開啟浮動歌詞才重試。診斷開關 `debug.moe.lyrics.trace`＝1（或 `moe_floating_lyrics` 的 `trace`）在 logcat（tag `MoeMediaIndex`）定期印 GL 執行緒統計。限制：只顯示有時間軸的歌詞；WebView 暫停時換歌，新歌詞要等頁面恢復才送到；「移動到狀態列」若讓歌詞區高過螢幕頂端，重新開啟或旋轉後會被夾回 y＝0。待實機驗收：位置比例與鎖定的存取、舊值搬移（手機與平板）、Windows 舊設定檔換算與多螢幕還原。

連續動畫與透明度（兩種歌詞視窗共用，`animation`：`none` 預設／`continuous`，工作列與浮動分開儲存）：所有歌詞接成一條，每行第一個字形的中心在該行開始時剛好對齊歌詞區中心（硬節點；`StripLayout.anchors`／Kotlin `firstGlyphCenters`），行級與逐字歌詞都以上述 `word_strip_knots`／`knot_cubic` 的單調 C1 曲線滑向下一行（`strip_cubic`／Kotlin `stripOffset` 只剩測試與備援）；只繪製會出現的行（`strip_window`／`FloatingLyricsRules.stripWindow`），不可把整首歌放進捲動條。透明度（實驗性，使用者核准，ADR 0041 D10，可整筆還原）只由固定在歌詞區的一張靜態遮罩決定（`centre_mask_stops`／Kotlin `WordLyricsRules.centreMaskStops`，共用向量 `centreMask`）：兩端由 0 漸變到次要透明度、往中心漸變到主要透明度（各視窗自己的 `mainOpacityPercent`／`secondaryOpacityPercent`，互不夾限；形狀見 ADR 0041 D10、5.4）；行級與逐字都用，取代邊緣淡出與每行透明度權重（連續模式沒有每行透明度與過渡）；只在寬度、字級或兩個透明度改變時重建。動畫「無」（卡拉 OK）不變，仍用邊緣淡出（`edge_fade_width`／`edge_fade_opacity`），整行以 `mainOpacityPercent` 繪製，`secondaryOpacityPercent` 無作用。兩個透明度隨各視窗自己的設定（`taskbar-lyrics-settings`、浮動設定、`floatingLyricsUpdate` 的 settings）送達，沒有獨立的廣播頻道。工作列與浮動歌詞同時開連續動畫有性能負擔，建議一次只開一種。

動畫設計規則（使用者定案，所有動畫適用）：（1）歌詞動畫必須跑滿螢幕更新率（120 Hz＝120 fps、60 Hz＝60 fps），所有歌詞視窗與主視窗同時動畫時也一樣，這是驗收標準；不得改成 60 fps 滑動。（2）CSS 的連續位置動畫只在移動至少 1 個實體像素時才更新，落後不到 1 px、每個目標精確到達；Windows 原生歌詞與 Android 浮動歌詞（GL 渲染）例外，以 1/8 px 次像素位移（靜止時取整數像素）；播放進度條與底欄／聲道矩陣跑馬燈（`dock-marquee.ts`）以 `linear` 次像素移動（測試 `tests/linear-position-animations.test.mjs`）。透明度淡化不受此限；例外：緩衝中進度條圓點的每秒一週期亮度脈動（見「播放進度時鐘」）。（3）每幀 CPU 越低越好：每幀只依時鐘算位置並提交有變的值，不在每幀點陣化、排版或模糊，能快取就快取，閒置時睡眠。時間規則（滑動對齊、200 ms 淡化、換行提前）不變。
