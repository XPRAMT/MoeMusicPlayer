# Android FLAC decoding: the Rust converter instead of the system MediaCodec

Status: Accepted

Decision date: 2026-10-26, Asia/Taipei (UTC+08:00)

## Context

Android played FLAC through Media3's `MediaCodecRenderer`, i.e. with whatever FLAC `MediaCodec` the device exposes. On a Sony Xperia G8142 (Android 9, API 28) 24-bit FLAC played no sound. Diagnostic logs (tag `MoeMediaIndex`, the temporary `flacdiag` logging) showed that `MediaCodecSelector.DEFAULT` returns only `OMX.qti.audio.decoder.flac` (`sw=true, hw=false, vendor=true`); the Google FLAC decoder is not exposed at all. That decoder plays 16-bit FLAC (`pcmEncoding=2`, 44.1 kHz) but fails every 24-bit FLAC (`pcmEncoding=21`, 48 and 96 kHz) with `ERROR(0x80001001)` in `dequeueOutputBuffer`, after logging `ExtendedACodec: no bitwidth, setting default bitwidth as 16 bits`. The device has no working system decoder for hi-res FLAC.

The first attempt (a `MediaCodecSelector` that put software FLAC decoders ahead of hardware ones, plus decoder fallback) could not help: there is no second decoder to fall back to, and the vendor decoder fails after it initialised, which decoder fallback does not catch. Other devices may ship equally broken vendor decoders, and nothing on the app side can repair them.

## Decision

- **FLAC on Android is decoded by the app**, through the bridge DSD (ADR 0016) and WavPack (ADR 0025) already use: the track is loaded as `moeflac:///path/to/file.flac`, the Kotlin `DsdDataSource` opens it through JNI (`DsdBridge`, `src-tauri/src/android_dsd.rs`) and reads a virtual WAV file of 32-bit float PCM at the file's own rate and channel count, and Media3's WAV extractor and float output play it. No `MediaCodec` is involved, so the result does not depend on the device. Windows is unchanged (rodio with Symphonia).
- **Decoder**: new crate `crates/player-flac` over Symphonia's pure-Rust FLAC decoder (`symphonia` 0.5.5, `flac` feature only, MPL-2.0, used unmodified as a library; the workspace already pins this version and credits Symphonia). `FlacReader` decodes to interleaved `f32` in ±1.0 (Symphonia left-aligns samples in `i32`, divided by `2^31`, so 8- to 24-bit samples are exact); `FlacWavStream` serves the 44-byte float WAV header plus the frames by byte range, with the length from STREAMINFO (a file that does not record its length is refused, like WavPack). claxon (Apache-2.0) was the alternative; Symphonia was chosen because the workspace already depends on it and its demuxer seeks.
- **Seeking** is sample accurate: the demuxer finds the FLAC frame that holds the wanted sample (through SEEKTABLE when present, otherwise a binary search over frame headers), and the samples of that frame before the wanted one are dropped. ExoPlayer seeks by byte position in the WAV, which maps to a frame index. Symphonia 0.5.5's packet parser keeps the header of the last parsed frame and, after a seek that lands exactly on a frame boundary, rejects later frames as out of sequence; a backward seek therefore reopens the demuxer on the same source first (only the metadata blocks are re-read). A seek that lands after the wanted sample (a damaged header) decodes from the start. A frame that fails to decode plays as silence of its length so the timeline and the WAV length stay right. A leading ID3v2 tag (which Symphonia's FLAC demuxer does not skip) is skipped.
- **Routing has one source of truth**: `player_formats::android_converter` (`AndroidConverter::Dsd` / `WavPack` / `Flac`) decides which formats Android converts. `android_dsd::to_converted_uri` gives a local `file://` track its converter scheme, `open` / `open_remote` pick the converter, and the load command sent to `PlaybackService` carries `converted` (`android_dsd::serves_converted_wav`), on which the service sets the MIME type to `audio/wav`; Kotlin no longer guesses from extensions. A remote FLAC (`moeremote://`) is converted inside `open_remote` like DSF and WavPack. Every local converter scheme is listed once in Kotlin (`LOCAL_CONVERTED_SCHEMES`), which the data source routing, the load check and the notification artwork path (`fileUriOfConverted`) use.
- **Limits**: `AudioTrack` tops out at 192 kHz, so a FLAC above that is refused (as for WavPack). Tags, cover, lyrics, duration and bit-depth display still come from `player-tags` (unchanged).
- The FLAC `MediaCodecSelector` and the `flacdiag` diagnostics are removed. `setEnableDecoderFallback(true)` stays: it only matters for formats Media3 still decodes with `MediaCodec` (MP3, AAC, Vorbis, Opus…), where trying the next decoder when one fails to initialise is harmless.

## Consequences

- FLAC playback on Android no longer depends on the device's decoders; decoding costs CPU in the app (FLAC decoding is cheap) and every byte goes through JNI, as for DSD and WavPack.
- Unit tests decode fixtures encoded by the reference `flac` encoder (16-bit stereo 44.1 kHz with a SEEKTABLE and 1152-sample blocks, 24-bit stereo 96 kHz, 24-bit mono 48 kHz without SEEKTABLE, 16-bit 6-channel) and compare against Symphonia's decode with the STREAMINFO MD5 verified; seeks forward and backward, the WAV header and byte-range reads are checked.
- Not yet verified on a device: playback, seeking and gapless transitions of 16- and 24-bit FLAC on the G8142 and the other test devices, local and remote; multichannel FLAC through `AudioTrack` float output.
