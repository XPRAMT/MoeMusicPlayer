# Authoritative playback progress and seek drafts

The audio worker snapshot is the only playhead authority outside an active user gesture. The progress control may show a local draft while dragging, but it commits once on a native range `change` or pointer release, discards on cancellation or track change, and immediately returns to the latest snapshot after commit or error; stale polls started before a seek are fenced from overwriting its ACK. Display duration may fall back to the active track's stored metadata when Rodio reports `Source::total_duration() == None`, but this fallback does not claim the decoder supports seeking: failed seek IPC preserves the snapshot and reports an error. This avoids keeping an optimistic position until a guessed timeout, which previously masked advancing audio snapshots after a seek.

Three update strategies were compared: retaining an optimistic target until a later snapshot approaches it or a timeout expires (the former implementation, which froze progress after a failed/stale seek); issuing a separate snapshot read after each seek (which adds IPC and still needs ordering against older polls); and returning the worker's post-command snapshot while fencing poll responses that began before the command (chosen). This follows the same authority boundary highlighted in ECHO's published design, where its audio host owns output-clock position and the UI only displays and controls playback; it does not adopt ECHO's Electron/host architecture. MusicPlayer2 is useful as a product-level local player reference, but its public documentation does not define this worker/Renderer snapshot contract. No third-party implementation code was copied.

Rodio's version-locked `0.22.2` API documents total duration as optional and seeking as fallible ([`Source`](https://docs.rs/rodio/0.22.2/rodio/source/trait.Source.html)); browser range controls provide distinct continuous `input` and committed `change` events ([MDN input](https://developer.mozilla.org/en-US/docs/Web/API/Element/input_event), [MDN change](https://developer.mozilla.org/en-US/docs/Web/API/HTMLElement/change_event)). ECHO describes a host-centered audio path where its native host owns output-clock position and the UI only displays and controls playback ([official project README](https://github.com/Moekotori/ECHO)); MusicPlayer2's repository identifies GPL-3.0 licensing ([official repository](https://github.com/zhongyang219/MusicPlayer2)). These were consulted as architecture/product references only; no code was copied.

## Decoder seek capability

The locked Rodio `0.22.2` feature set originally selected its `minimp3`, `claxon`, and `lewton` decoders for MP3, FLAC, and Vorbis. Their `Source::try_seek` implementations explicitly return `NotSupported`; `Decoder::try_from(File)` supplies byte length and seekability metadata but cannot add seek support to those decoder implementations. A checked-in synthetic MP3 reproduced the exact backend error. The Windows player now selects Rodio's matching Symphonia `mp3`, `flac`, `vorbis`, and `wav` features so these existing formats share its seek-capable decoder path. Integration tests use synthetic MP3, FLAC, Ogg/Vorbis, and WAV files to check duration and seek position; unsupported seeks remain errors and never advance the authoritative snapshot optimistically. Rodio `0.22.2` documents file byte length as necessary for reliable seek/duration in formats such as MP3 and exposes this through `Decoder::try_from(File)` ([versioned decoder docs](https://docs.rs/rodio/0.22.2/rodio/decoder/struct.Decoder.html)). Symphonia `0.5.5` is MPL-2.0; it is used as a dependency, with no copied source.

## Playback-rate investigation status

The report that playback is fast from the start is treated separately from seek. The user-provided candidate previous release is `7c423d6` based on executable modification time, but no embedded build hash proves that mapping. Source comparison from that commit through current HEAD shows no `player-audio-windows` or Rodio feature/config change; the only playback snapshot change is metadata duration fallback for display. Rodio `0.22.2` initializes player speed to `1.0`, the app contains no `set_speed` call, and TrackPosition follows the speed wrapper as Rodio recommends. Synthetic PCM and MP3 decoded through a 96 kHz offline mixer report about one second of audio position per 96,000 output frames in both debug and release tests. This is a sample-count/timebase check only; it does not measure a real WASAPI endpoint clock and does not invalidate the user's audible report. Do not open a second output stream or replace the running isolated Tauri window for this investigation. A known-duration track still needs manual wall-clock playback validation in that isolated window.

mpv is the external interactive-seek reference: its official On Screen Controller documentation describes mouse-click seeking, and its `osc.lua` implements a seekbar; its input API separates seek position from playback properties, documenting `time-pos` as current file time and `audio-pts` as a more frequently updated audio position that includes driver delay. We use these as behavior/contract references only and do not copy code ([OSC documentation](https://github.com/mpv-player/mpv/blob/master/DOCS/man/osc.rst), [OSC implementation](https://github.com/mpv-player/mpv/blob/master/player/lua/osc.lua), [input/property documentation](https://github.com/mpv-player/mpv/blob/master/DOCS/man/input.rst)). The referenced `LICENSE.GPL` is GNU GPL version 2; no mpv code or dependency is included ([license](https://github.com/mpv-player/mpv/blob/master/LICENSE.GPL)).
