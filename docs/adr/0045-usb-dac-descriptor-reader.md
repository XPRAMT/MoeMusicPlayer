# USB DAC descriptor reader (first step toward USB exclusive output)

Status: Accepted (built and unit-tested; not yet run on a device)

Decision date: 2026-10-28, Asia/Taipei (UTC+08:00)

## Context

ADR 0044 lists USB exclusive access as future work: playing to a USB DAC directly over USB, bypassing the Android mixer. Before any such output can be designed, the player must know what a DAC really offers: its USB Audio Class version, how it keeps time (asynchronous with a feedback endpoint, adaptive, synchronous), its clock sources, its hardware volume and mute, and for every alternate setting of its streaming interface the format, sample size, channels, rates and endpoints. Android's `AudioDeviceInfo` (ADR 0044) gives only rates and channels after the platform's USB driver has chosen a setting. The USB descriptors say everything, and reading them does not disturb the platform driver that is playing.

The user's reference device is a Sony DAC ("Sony Audio", VID 054C, PID 0B8C): UAC 2, Audio Control interface 0, streaming interface 1 with alt 0 (zero bandwidth) and alts 1–7, an isochronous asynchronous OUT endpoint 0x01 (bmAttributes 0x05, wMaxPacketSize 1024, bInterval 1) and a feedback IN endpoint 0x81 (0x11, 4 bytes, bInterval 4).

## Decision

- **Read only, nothing else.** `UsbAudioReader` lists the attached devices with an interface of class 1 (Audio), asks for USB permission with `UsbManager.requestPermission` (the system dialog, a broadcast `PendingIntent` to the app's own package, receiver not exported) only when the user presses 「讀取 USB 規格」 on a USB card, then `openDevice` → `getRawDescriptors()` → `close()` at once. It never claims an interface, never selects an alternate setting and never sends a control transfer, so the platform's driver and playback are untouched. A refusal is remembered for the process (UsbManager keeps none) so the page can say 「未取得 USB 權限」; a dialog left unanswered gives up after 60 s.
- **Parser** (`UsbAudioDescriptors`, pure Kotlin, written from the USB Audio Class 1.0 and 2.0 specifications): walks the descriptors by bLength (stops at a zero length; a truncated or unknown descriptor is skipped, never thrown on). Version: interface protocol 0x20 (UAC2) or 0x30 (UAC3), else the AC header's bcdADC. Audio Control: input/output terminals (type, associated terminal, source, UAC2 clock), feature units (master and per-channel mute and volume present: UAC1 D0/D1 of bmaControls, UAC2 any non-zero 2-bit field), UAC2 clock sources (external / internal fixed / variable / programmable, SOF sync, frequency and validity controls) and clock selectors. Audio Streaming, per interface and alternate setting: terminal link, format (UAC1 wFormatTag; UAC2 bFormatType and bmFormats, bit 31 = raw data such as DSD; Type II and III named), subslot/subframe bytes, bit resolution, channels, UAC1 discrete rates or continuous range, and each endpoint (address, direction, transfer, sync and usage type, wMaxPacketSize split into size and extra high-bandwidth transactions, bInterval). UAC2 rates come from the clock source at runtime (a GET RANGE request): they are not asked, so they are null. UAC3 is recognised, its units and formats are not parsed. Several audio configurations: the first is the top level, the others are under `otherConfigurations`.
- **Interface**: plugin command `usbAudioDescriptors { request }` through the existing `audio_output` bridge, Tauri command `android_usb_audio_descriptors` (null on other platforms) → `{ supported, devices: [{ name, vendorId, productId, manufacturer, product, permission: granted | denied | notAsked, error?, uacVersion, controls, streams, otherConfigurations, raw }] }`. The JSON is also logged to logcat (tag `MoeMediaIndex`, in numbered parts because logcat cuts long lines).
- **Page**: the USB card in Settings → playback (`AndroidOutputDevicesSettings.svelte`) has 「讀取 USB 規格」; the result is a compact list (`usb-audio-descriptors.js`), e.g. 「UAC 2．非同步（有回饋）」, 「硬體音量：有．靜音：有」, 「時脈：內部可程式（可設定頻率）」, 「設定 1：PCM．16bit（2 byte）．2 聲道（端點 0x01 輸出．非同步．1024 byte．間隔 1；端點 0x81 回饋．4 byte．間隔 4）」, and the raw bytes in a collapsible 「原始描述元」 with a copy button. The area is marked `data-own-click` (and `<summary>` is an own control) so it never chooses the card (`output-device-card.js`). Every USB card shows all attached USB audio devices: `AudioDeviceInfo` and `UsbDevice` share no identifier, so a card cannot be matched to one USB device reliably. USB permission is not a runtime permission, so the explanation panel of ADR 0039 does not apply; the button itself is the user's request.
- **Licence**: EchoTide-Music (AGPL) has a USB exclusive mode; none of its code was read into or copied into this project (AGENTS.md: no GPL/AGPL code). The parser is written from the class specifications.

## System mixer formats (Android 14+)

- **What**: the same 「讀取 USB 規格」 press also asks Android which mixer formats it would open for the card's output device. The page passes the card's `AudioDeviceInfo` id (`deviceId`, from the row key `device-<id>`); when it is absent or no longer attached, every USB output (`TYPE_USB_DEVICE`, `TYPE_USB_HEADSET`, `TYPE_USB_ACCESSORY`) is asked. `AudioManager.getSupportedMixerAttributes(device)` and `getPreferredMixerAttributes(USAGE_MEDIA, device)` only; below Android 14 the answer is `{ supported: false, reason: "requiresAndroid14" }`. Neither query needs USB permission or opens the device. An exception is reported per device as text (`error`).
- **Read only**: `setPreferredMixerAttributes` and `clearPreferredMixerAttributes` are never called, no AudioTrack is opened and no setting changes (a test checks the reader's source for this).
- **Shape**: the answer's `mixerAttributes` = `{ supported, reason?, devices: [{ id, type, productName, groups, bitPerfect, preferred, error? }] }`. The pure `MixerAttributesRules` groups the entries by behavior (bit-perfect first, then default, then unknown values kept as `behaviorValue`), then encoding (deepest first; an unknown encoding is `other` with `encodingValue`) and channel mask, each group with its distinct rates ascending (an unspecified rate is left out). The same JSON is logged as `USB mixer attributes i/N: `.
- **Page**: 「系統混音器格式」 under the descriptors, one line per group in the separators of `output-format.js`, e.g. 「位元完美：PCM 32bit．48, 96, 192 kHz．2 聲道」, 「一般：PCM 16bit．48 kHz．2 聲道」; without any bit-perfect entry 「此系統未提供位元完美模式」 comes first (default entries still listed); a set preference is 「目前偏好：…」; below Android 14 「需要 Android 14 以上才能查詢」 (`describeMixerAttributes` in `usb-audio-descriptors.js`).
- **Limits**: a vendor build may return an empty list even for a DAC that could take bit-perfect streams. The list is what the audio policy is willing to open for the device, not what the DAC receives; it is most likely built from the same rate list the policy already reports (the card's `AudioDeviceInfo` rates), so it says nothing about the USB alternate settings above. Whether a bit-perfect entry really reaches the DAC unchanged can only be told by a later output path that uses it.

## Consequences

- Exclusive USB output itself (claiming the streaming interface, choosing an alternate setting, setting the clock, isochronous transfers with feedback) is future work and will need its own ADR; this step changes no playback path.
- Unit tests: Kotlin `UsbAudioDescriptorsTest` (a UAC2 fixture shaped like the Sony DAC, a UAC1 fixture with discrete and continuous rates, high-bandwidth packet sizes, truncation at every byte, random bytes, too-short class descriptors, non-audio interfaces); JS `tests/usb-audio-descriptors.test.mjs` (lines, sync wording, endpoints, permission and read failures, hex, the card-click rule).
- Unit tests for the mixer query: Kotlin `MixerAttributesRulesTest` (empty list, default only, bit-perfect entries, below Android 14, unknown behavior and encoding, channel mask fallback, error text); JS `tests/usb-mixer-attributes.test.mjs`.
- Needs device verification: the permission dialog and its broadcast on Android 12–15, `getRawDescriptors` on the Sony DAC and other DACs, that reading while playing does not interrupt playback, and what `getSupportedMixerAttributes` returns on Android 14+ devices for a USB DAC.
